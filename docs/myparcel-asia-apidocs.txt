API Documentation
Version 2.1

This is documentation for public API to MyParcel Asia. This API enable your system to be able to use MyParcel Asia engine to generate consignment note.

General Guidelines
ONLY POST request required. Other method is not available
api_key parameter need to always be sent in POST parameter for verification
Base url for PRODUCTION endpoint is https://app.myparcelasia.com/apiv2/{endpoint}
Base url for DEVELOPMENT endpoint is https://demo.myparcelasia.com/apiv2/{endpoint}
POST HTTP Query
All api call can only be accessed via any HTTP software such as cURL and plain AJAX as POST operation. No other verb is in service.

All parameter sent should be a standard POST parameter. No other input (get, body) is available.

All parameter should follow the required format and validation requirement to ensure success in operation. Helpful error message will accompany all error in validation and processing the required action.

Testing / Demo Keys
For development and testing purpose, please register demo account at https://demo.myparcelasia.com/ and generate key like above guidance.

You also need to use https://demo.myparcelasia.com/ as endpoint.

All demo credit topup request will be auto approved and all shipment will have not-working fake tracking number. Other than that, everything will be the same.

Verification
Verification done via api_key match between sent api_key and api_key in our backend. Mismatch api_key will return error and endpoint will not be processed.

Please take note that api_key value need to be sent as POST Parameter along with other parameters. NOT in HTTP Authentication parameter.

Response object has 5 separate section. Explanation as below:

Parameter	Explanation
status	will only return TRUE or FALSE to indicate the status of call.
message	will contain verbose response accompanying the status.
data	will contain specific object that is a result of endpoint processing. It may differ from one endpoint to another.
hash	contain a hash key of all the returned parameter exluding hash itself and meta. Optional for you to check the validity of the return object. Hash calculation will be presented below.
meta	is miscelanious data that can help in developing the integration and can also be helpful in debugging integration errors.
Hash Calculation
Hash was generate by simple formula: an array with parameter for status, message and data IN THAT ORDER which then encoded as JSON string and concatenate with api_secret accompanying the api_key in usage. The string then get hash with md5 function to return a 32 character length hash result.

<?php
  $ret['status'] = $status;
  $ret['message'] = $msg;
  $ret['data'] = $data;
  $ret['meta'] = $meta;
  $hash = md5(json_encode($ret).$api_secret);

?>
General Flow (Cart Flow)
As customer facing API, this integration was meant to be used in system that manage purchased item as fulfillment. In general, your system should have a listing or orders that need to be processed.

From there, your user can select items/orders that they like to generate consignment note and proceed with MyParcel Asia API.

User select items to be processed by MyParcel Asia
User key in postcode from & to and get list of quotes
User select quotes they aggree with
System verify that user has enough balance, if not, user has the option to topup their account balance
If enough balance, user will need to fill in receiver details
Done all details, user checkout to confirm balance reduction and get connotes to be downloaded
End
Bulk Operation (Bulk Flow)
Some of you might better use a bulk flow to create shipment, as it is more simpler to create a working consignment note label.

This Bulk Flow can create multiple shipments and check it out automatically which directly return a label url.

Check multiple shipment price.
Create consignment note label for multiple shipment
Get multiple shipment details.
